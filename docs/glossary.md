# Glossary

The single source of this domain's terms. Code, tests, events, and UI use
these terms and no others — do not introduce a synonym for a term already
listed here.

| Term                               | Definition                                                                                                                                                                                               | Is not                                                                                                                                                                                                                                   |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Phrase**                         | One French/English pair. The unit of learning. Entity local to its Deck; has an `id` so the correction and edit screens can address it under shuffle.                                                    | Not a "word" — the directive was corrected: these are phrases. Not a flashcard: it has no schedule, no score.                                                                                                                            |
| **French text** / **English text** | The two halves of a Phrase. Fields `french`, `english`. French is the side that is drilled three times; English is the side spoken once.                                                                 | Not `front`/`back` (no card metaphor), not `target`/`native` (generality not yet earned — refused deliberately for a single-user, single-language app; a second language is an additive migration, not a reason to provision now).       |
| **Deck**                           | A named collection of Phrases for one context (`home`, `friends`, `work`, `formal`, `climbing`). The thing the owner called a "list". The aggregate root; the unit of persistence.                       | Not `List` — collides fatally with the data structure; a type named `List` holding an array is two concepts in one word. Not `Context` — collides with React Context and general programming vocabulary. Not an Anki deck: no scheduler. |
| **Cadence**                        | The fixed playback pattern applied to one Phrase: **FR · pause · FR · pause · EN · pause · FR · pause**. Defined as pure data (a sequence of Steps), not as behaviour. The heart of the product.         | Not "phrasing" (the owner's word — collides with Phrase itself), not a setting: it is fixed in v1.                                                                                                                                       |
| **Step**                           | One element of the Cadence: either an Utterance (speak the French text or the English text) or a Pause (silence of a stated duration).                                                                   |                                                                                                                                                                                                                                          |
| **Rep**                            | One Phrase played through the full Cadence, start to finish. The unit of progress inside a Drill.                                                                                                        | Not a "review" — no scheduling connotation wanted.                                                                                                                                                                                       |
| **Drill**                          | One run-through: an ordered sequence of Reps over the Phrases of one Deck or one Mix, with a position, playing/paused/stopped state. In-memory only; not persisted.                                      | Not a "session" — that word is taken by the workflow system and by web infrastructure.                                                                                                                                                   |
| **Shuffle**                        | Random reordering (Fisher–Yates) of the Phrases at Drill start. A property of the Drill, not of the Deck: the Deck keeps its author order.                                                               |                                                                                                                                                                                                                                          |
| **Mix**                            | A named, saved selection of Decks, drilled as one run: their Phrases pooled in Mix order and shuffled. The owner's word is "join"; corrected deliberately. An entity — `id`, `name`, and the **ids** of its Decks (`deckIds`), persisted beside them (schema v4, T059). Saving, renaming, editing or deleting a Mix never touches a Deck, and deleting a Deck never touches a Mix: a Deck deleted out from under one is skipped when the Mix resolves, and its id is kept so a restored Deck rejoins it. | Not a merge: the source Decks are untouched. **No longer ephemeral** — it was, until T059, when the owner asked to save, edit and delete Mixes. Not a copy of its Decks: it holds ids, never Phrases, so an edited Deck changes every Mix that names it. A selection started *without* being saved is not a Mix — it leaves nothing behind, and is simply a Drill over several Decks. |
| **Scan**                           | One photo of handwritten phrases submitted for reading. Input to the Import port.                                                                                                                        |                                                                                                                                                                                                                                          |
| **Draft Phrase**                   | A French/English pair proposed by the vision model from a Scan. Exists only on the correction screen; becomes a Phrase only when confirmed into a Deck. Nothing reaches storage un-reviewed.             | Not a Phrase — the distinction is the whole point of the correction screen.                                                                                                                                                              |
| **Phrase Candidate**                | A machine-proposed rendering of the other side of a Phrase, offered when adding one (T057): she types one side, one or more Candidates are proposed for the other, optionally labelled with the register they represent (`tu`, `vous`, `formal`, `casual`) when the phrase genuinely supports more than one natural rendering — one unlabelled Candidate is a correct, complete result, not a degraded one. Exists only on the Add sheet; each one she accepts becomes its own Phrase, into a Deck chosen at accept time. Nothing reaches storage un-reviewed. | Not a Draft Phrase — a Draft Phrase comes from a Scan and already has both sides; a Phrase Candidate proposes only the side not yet typed. Not a Phrase — no `id`, does not exist until accepted. |
| **Voice**                          | The text-to-speech voice a Clip is rendered in: `provider`, `modelId`, `voiceId` — two thirds of a Clip's content address. Chosen from a curated catalogue (`voice-catalogue.ts`); the one she has chosen is the **pinned voice**, and it decides exactly one thing (T067): what the NEXT Phrase with no audio is generated in. It rides in the `Library` envelope as its own named field, so a new phone restores the preference; two devices disagreeing resolve by last writer wins, and an envelope carrying none never clears one. | Not a property of the app, of a Deck, or of a Phrase — it belongs to each Clip. Not something that can invalidate audio: re-pinning leaves every existing Clip playable, and playback prefers the pinned voice only where a Clip exists in it. Not a credential, and not the rest of the `settings` record, none of which travels. |
| **Clip**                           | The cached audio rendering of one side of one Phrase, in one voice. Content-addressed by a hash of `provider\|modelId\|voiceId\|lang\|text`, so a given voice-and-statement is generated exactly once, ever, and an edited Phrase points at a different hash — staleness is impossible by construction. **Its voice is a property of the Clip, not of the app (T067):** one Phrase may hold Clips in several voices at once, they all stay playable, and pinning another **Voice** invalidates none of them. Derived, regenerable; never user data. The cache holding them is **bounded** and evicts (see **Eviction**). | Not stored data in the export sense — excluded from `Library`/`exportAll()`. Not a Phrase's identity: losing every Clip loses nothing but generation time. No longer orphaned by a voice change — that was true until T067 and cost a whole library's regeneration for a preference. |
| **Eviction**                       | Deleting cached Clips to keep the clip cache under its ceiling (200 MB, T036), least recently *played* first — `get()` counts as playing, the readiness sweep's `has()` does not. Runs on any `put` that crosses the line **and on the first index build of every launch (T076)**, because a phone that arrived over the ceiling and generates nothing would otherwise never shrink. Exists because on iOS storage pressure is itself an eviction trigger, so an unbounded audio cache is on course to make the browser discard the whole origin, Phrases included. It can reach the `clips` and `clipMeta` stores and nothing else, structurally. | Not a deletion of anything of hers: it cannot touch a Phrase, a Deck, a Mix or a Tombstone, and refusing to be able to is the point. Not the same as an **orphan**; eviction removes Clips that are still wanted, to buy room. |
| **Orphan**                         | A record whose referent is gone. Two of them, one relation: an **orphaned Clip** is audio nothing points at any more (an edited Phrase points at a different hash; **not** a re-pinned voice, which since T067 leaves every Clip in use), and an **orphaned index row** is a `clipMeta` row whose Clip is gone. Eviction no longer makes them — the Clip and its row go in one transaction (T078) — so what is left is a phone carrying rows the old two-step eviction orphaned, and audio the browser dropped on its own. Both are derived, so both are deleted on sight: the index is reconciled against the audio, in both directions, before the ceiling is applied to it (T076, docs/scale.md §8). | Never anything of hers: a Phrase, Deck, Mix or Tombstone cannot be orphaned, because nothing of hers is derived from anything else. Not a harmless leak either — an orphaned index row is charged against the **Eviction** ceiling and makes `has()` promise audio that is gone. |
| **Session token**                  | The device's identity on the server (T050, `docs/server.md`): an opaque 32-byte random token, issued by `POST /api/login` and held only client-side (`localStorage`); the server stores only its SHA-256 hash, keyed to a `users` row, in a `sessions` table with a 30-day expiry. Sent as `Authorization: Bearer <token>` on every `/api/*` call; identifies which library is hers, nothing more. | Not a JWT — it carries no claims and cannot be verified offline; every use is a database lookup, which is what makes revocation (delete the row) free. Not a provider API key — the device never holds one of those. Not the deleted **Library key** (below) it replaces: that was self-issued and unauthenticated; this is issued by the server after a username/password check. |
| **Library key** *(retired, T050)*  | The device's pre-login identity (T041–T049): 64 lowercase hex characters generated on-device and shown in the open in Settings. Replaced by **Session token** above — kept here only so old references (commit history, prior task notes) resolve to a real term. | Not in use. Do not reintroduce. |
| **Diagnostic report**              | The plain-text snapshot the Diagnostics screen shows and its one control copies whole (`docs/design.md` §3.7): build sha/timestamp, pinned voice, Clips ready vs total Phrases (counts only), storage usage/quota, last sync, and the last several entries from the on-device error log. Built so a remote, non-technical user can answer "it's not working" without guessing. | Not a support ticket, not sent anywhere automatically — stays on-device until pasted into a message by hand. Not a log of everything: the error log it draws from is a bounded ring buffer (`ERROR_LOG_CAP`), not an unbounded history.  |
| **Backup age**                     | How long since her Library was last safe somewhere other than this phone: the elapsed whole days since the more recent of the last successful server sync and the last backup file she exported herself (`domain/backup-age.ts`). Has four levels — `never`, `fresh` (under 7 days), `aging` (7–29), `overdue` (30+) — and the level, not the number, decides how loudly the app states it and how far it follows her. Because sync runs after every save, an age that climbs is the app's only visible signal that **sync has been failing silently**. | Not a reminder and not a nudge: it is a stated fact with no dismiss control, it never repeats, and it never interrupts. Not a measure of how old her phrases are. Not affected by Clips, which are derived and regenerable. |
| **Tombstone**                      | The record that a Deck or a Mix was deleted, and when: `{ id, kind, deletedAt }`, kept after the thing it names is gone and carried in the `Library` envelope (T060). It is what lets sync merge two devices instead of overwriting one with the other — without it, a merge cannot tell "she deleted this" from "this device has never seen it", so every device still holding the Deck pushes it back and a delete never sticks. Never garbage-collected: any expiry window is also the window after which an offline device resurrects her data. | Not an undo — it holds nothing of the Deck's contents and cannot restore it. Not a soft delete: the Deck record itself is really gone from the `decks` store, and a Tombstone is a separate, tiny record in its own store. |
| **Split id**                       | The id given to the second and later Deck or Mix holding an id another already holds: `${id}-2`, `${id}-3`, …, skipping any the library already carries (T090, `duplicate-ids.ts`). Applied by `importAll` and `updateAll`, because `decks` and `mixes` are keyed by `id` and one `put` per record would otherwise let the second overwrite the first — a whole Deck gone from disk with nothing said. Deterministic, so repeated merges converge; collision-free, so the repair cannot itself overwrite a record. Both records keep their content and their names, so she sees two Decks and merges or deletes them herself. | Not a new Deck — it is one of two records that were already there. Not a merge and not a refusal: `mergeLibraries` keeps both (T086) and the store splits them, because refusing a restore file that may be her only copy costs her everything in it to avoid a defect whose cost is one tap. Not applied to a Tombstone, whose id names the record it deletes. |
| **Sync**                           | One round-trip that leaves this device's library and the server's holding the same thing: pull, merge, write the merge back locally, push it. Runs by itself (T034, `docs/sync.md`) — at launch, after every change (debounced), on reconnect, and when the app is backgrounded. Never destructive: a push carries the merge of both sides, so it can add records to the server copy and never remove one. | Not a backup — a backup is a file she exports and keeps (`docs/design.md` §3.6); a Sync is continuous and has no artefact she holds. Not an upload: it reads before it writes, always. Not something she starts — there is no sync control anywhere in the app. |
| **Sync Baseline**                  | The last whole-library snapshot this device and the server are known to have agreed on: what this device pushed and the server accepted. Held per-device, never sent anywhere. It is the common ancestor `mergeLibraries` needs to tell "changed here" from "changed there", which is what lets two devices edit different Phrases of one Deck without either losing a Phrase (T034). It is also causal rather than chronological: a Tombstone deletes only a record unchanged from it (T070), which is why a restore from file sets it EMPTY — nothing on this device is agreed with the server afterwards, so every restored record outranks a deletion the server still holds (T072). | Not a backup, not history — one snapshot, replaced on every successful push, and emptied by a restore as one operation with the restore's own write (T081). Not user data: derived and regenerable, and losing it costs the next merge its precision (it falls back to whole-record last-write-wins) and nothing else — which is why one written under a schema version this build does not read is treated as absent rather than refused (T081). |
| **Refused write**                  | A write to this phone's own storage that the device would not take: a `QuotaExceededError` when the origin is full, an IndexedDB transaction iOS aborted under memory pressure, a `versionchange` from another surface. Distinct from anything to do with the server. Every write in the app is optimistic — the screen changes first — so a Refused write is the one event that can leave a Phrase on screen that is not on disk, and it always produces two things together (T069): the screens are re-read from the stores so they show what is really held, and the **Write failure notice** states which change did not survive. A Refused write is never announced to the sync engine; there is nothing to send. | Not a sync failure — sync has its own line, which stays quiet because a sync that has not happened yet has lost nothing. Not something the error log alone answers for: the Diagnostics screen is not a place she goes. |
| **Write failure notice**           | The single alert in the app (`src/ui/WriteFailureNotice.tsx`): one sentence naming what did not save, one standing sentence saying the phone may be out of space and that the screen now shows what is really stored, and a control to put it away. Fixed to the top of whatever screen she is on, including a running Drill. | Not a toast — it does not time out. Not the sync line, which is standing information about the server and is deliberately quiet. Not one per failure: the most recent one is shown, because two of these at once is one condition, not two. |
